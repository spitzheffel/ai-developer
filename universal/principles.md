# 通用行为规则

每条都可判定违反与否，审查时按编号引用（如「违反 #5」）。

1. **只改任务范围内的文件。** 发现范围外问题，报告（建议记入[痛点日志](../docs/pain-log.md)），不顺手修。
   - ❌ 顺手重构了无关文件里的旧代码　✅ 「utils/date.ts 疑似时区 bug，本次未动，建议另开任务」
2. **新增或升级依赖前，先说明理由并征得同意。** 决策流程见[轮子vs自研](../process/build-vs-buy.md)。
3. **动手前列出你依赖的假设；不确定就问，不要猜着做。**
4. **新建函数/组件/工具前，先查项目 CLAUDE.md 的模块地图，并全局搜索既有实现。**
5. **禁止为通过检查而跳过、删除、弱化测试或断言；禁止空实现交差。**
   - ❌ 把 `expect(total).toBe(3)` 改成 `toBeDefined()` 换 CI 变绿　✅ 修实现直到原断言通过，或明说修不动
6. **用不熟悉或新版本的库 API 前先查官方文档，不凭记忆写。** 记忆里的 API 签名默认过期。
7. **一行能写的逻辑不引依赖**（微依赖禁止）。
8. **绝不自研清单——以下必须用成熟库：** 加密/哈希、鉴权协议、时区与日历运算、货币精度计算、SQL 转义、HTML 清洗。逐项原因见[轮子vs自研](../process/build-vs-buy.md)。
9. **声称完成前，跑完[完成定义](../process/definition-of-done.md)要求的全部检查，并贴出真实输出。**
   - ❌ 「所有测试应该能通过」　✅ 实跑后贴出：`Tests: 42 passed, 0 failed`
10. **做不完就明说哪些没做；不留伪装成完成的 TODO 占位。**
    - ❌ `return []; // TODO: 过滤` 却报告「已完成」　✅ 「过滤未实现，当前返回空数组，卡在 X」
11. **密钥不硬编码。** 一律 `.env` + `.env.example` 模式，示例文件只放占位名。
12. **修 bug 先复现并取运行时证据（按 request_id 过滤结构化日志 / 前端看 console），禁止未读证据就改码；修完回查同一证据转好。**（〔试用〕来源：调研 2026-11，docs/research/adoption-plan.md）
    - ❌ 看报错栈猜原因直接改，改完说「应该好了」　✅ 复现→按 request_id 取日志定位→改→重跑同一请求，日志里错误消失

新条目只从[痛点日志](../docs/pain-log.md)晋升：同一坑踩两次、违反可判定、跨技术栈——三者齐备才进本文件。
