> 给用 Claude Code 干活的你：开新会话前、会话变长变笨时、同一问题反复修不好时翻开。对应阶段7 会话管理，出口通向阶段8 沉淀。

# 阶段7：会话管理

上下文是会话里最贵的资源：它有限、会被压缩，而且里面的一切——包括失败尝试——都会影响后续输出。本文所有规则服务同一件事：**重要信息活在文件里，垃圾随会话一起扔掉。**

## 速查

| 情形 | 动作 |
| --- | --- |
| 换任务 | `/clear` + 按 [task-brief.md](task-brief.md) 写新任务简述 |
| 上下文快满 / 回答变差 | 落盘方案与进度 → `/clear` → 按 checklist 续作 |
| 同一问题两次纠正无效 | 止损：回滚工作区 + `/clear` + 改进任务简述重来 |
| 要读很多文件才能动手 | 派子代理探索，只带结论回主会话 |
| 发现新约定 / 有效纠正 | 写进项目 CLAUDE.md，并记一条[痛点日志](../docs/pain-log.md) |

## 1. 一个会话一个任务

- 一个任务结束就 `/clear`，开全新空上下文；CLAUDE.md 和 auto memory 不受影响。可用 `/clear 名字` 给上段对话留名，之后 `/resume` 找回。
- 多任务共用一个会话会互相污染：上个任务读过的文件、被否掉的方案，会被当成当前任务的事实。
- `/compact` 只是总结压缩当前对话（细节有损），不是任务边界；任务边界永远用 `/clear`。
- ❌ 修完登录 bug 接着说"顺便把导出做了" ✅ `/clear` 后用新任务简述开工

## 2. 重要的东西必须落盘

上下文满了会被压缩（自动或手动 `/compact`），压缩就是丢细节。只存在对话里的信息，默认当作会丢。

| 信息 | 落到哪 |
| --- | --- |
| 方案与决策 | 项目内 plan.md（模板：[plan.md.template](../templates/plan.md.template)） |
| 多步任务进度 | checklist 文件（见第 5 节） |
| 新约定、有效纠正 | 项目 CLAUDE.md（模板：[CLAUDE.md.template](../templates/CLAUDE.md.template)） |

- 判定标准：此刻 `/clear` 重开，只靠文件能否无损续作？不能，就还有东西没落盘。
- ❌ "按我们刚才讨论的方案继续" ✅ "方案已写入 plan.md，从第 3 步继续"

## 3. 止损规则

**同一问题，两次纠正无效 → 止损：回滚工作区 + `/clear` + 改进任务简述重来。**

- 重来不等于从零：把失败路径写进新任务简述的非目标/排除项——"不要用 X 方案，已验证因 Y 不通"。
- 对会话克服沉没成本：纠缠越久，上下文里错误假设越多，每轮输出越糟；重开几乎总是更便宜。
- 止损时顺手在[痛点日志](../docs/pain-log.md)记一条：这是阶段8 沉淀的原料。
- ❌ 第三次说"不对，你再仔细看看" ✅ 回滚，改任务简述，重开

## 4. 大范围探索交给子代理

跨多文件找代码、搞清一个子系统怎么工作，这类"读得多、留得少"的活交给子代理，主会话只接收摘要。

- 主上下文只装：任务简述、方案、当前改动涉及的文件。几十个文件的原文灌进主会话，等于提前触发压缩。
- ❌ 主会话连开 20 个文件找调用方 ✅ "派子代理找出所有调用 parseConfig 的位置，汇总成 文件:行号 清单"

## 5. 长任务：用 checklist 续作

预计一次会话做不完的任务，开工第一步先生成 checklist 文件落盘（如 docs/plans/<任务>-checklist.md）：

- 每完成一步立刻勾掉并一句话注明结果；新发现的步骤追加到表尾。
- 续作时新会话第一句："读 <checklist 路径>，从第一个未勾项继续。"
- 效果：`/clear` 变成零成本操作——上下文随时可扔，进度永远在文件里。

## 6. 沉淀快捷方式（阶段8 的入口）

- `/memory`：列出并打开用户级/项目级 CLAUDE.md 等记忆文件（不存在会先创建）。发现约定当场写进去，别等"以后整理"。
- 以 `#` 开头的消息快捷追加记忆：官方文档未确认此行为，以你的版本实测为准；拿不准就直接用 `/memory`。
- 写之前过三连筛：能用配置/钩子强制的，去改 [hooks](../claude-code/hooks.md)，不要写成 prose 规则。

## 7. auto memory 的边界

Claude Code 本地会话默认开启 auto memory：把纠正、偏好等自动记到 `~/.claude/projects/<项目>/memory/`，入口是 MEMORY.md。对它的正确预期：

- 每次会话只自动加载 MEMORY.md 的前 200 行或 25KB（先到为准）；只存本机，不跨机器同步；子代理默认不加载（fork 的子会话除外）。
- 它记的是零散事实，不是系统化规则，不能指望它替你维护约定；开关走 `/memory`。
- 结论：关键约定必须显式落盘到项目 CLAUDE.md——进 git、全员共享、每次在场；auto memory 只当意外之喜。
- CLAUDE.md 与 auto memory 都只是上下文，不构成强制；要硬性阻断某类动作，用 PreToolUse hook（见 [hooks](../claude-code/hooks.md)）。
