# 轮子vs自研（build-vs-buy）

## 问题

AI 的默认行为是闷头实现眼前逻辑，不会主动触发「业内有没有成熟方案」这个判断，于是两头犯错——该用库的手搓出劣化版，不该引的又为三行代码拖进一个包；本文件的全部作用，是把这个沉默决策变成显式决策。

## 触发条件（满足任一即触发）

- 要实现的是**非业务的通用能力**：重试、缓存、日期处理、数据校验、格式解析、并发控制、分页、限流……凡是「换个项目也原样需要」的东西。
- 预计实现超过约 **30-50 行**（精确阈值按当前栈 README 第 4 节校准）。
- 涉及**易错域**：时间、并发、安全、解析——哪怕只有十行也触发。

## 触发后必须

1. 停下，先不写实现代码。
2. 给出 build-vs-buy 对比，固定四项：**候选库**（1-3 个）、**维护状态**（最近发版、issue 响应、使用量）、**引入成本**（体积、传递依赖、API 学习量）、**建议+一句理由**。
3. 等拍板再动手——新依赖本来就要征得同意（principles #2）。
4. 结论落盘：选了库 → 写进项目 CLAUDE.md 的选型清单；决定自研 → 在[任务简述](task-brief.md)里记一句为什么。

对比产出长这样（示例）：

```text
要做：HTTP 请求失败重试（指数退避+抖动）
候选：p-retry —— 维护：活跃；引入成本：包小、API 面窄
自研：约 60 行 + 退避/上限/错误分类的测试，落在易错域（时间+并发）
建议：用 p-retry。理由：支撑域能力，踩坑成本远高于引入成本。
```

## 默认倾向

| 域 | 默认 | 判别问题 |
| --- | --- | --- |
| 支撑域（重试/缓存/解析/鉴权等基础设施） | 用成熟库 | 「这段代码换个产品能原样搬走吗？」——能，就是支撑域 |
| 核心域（业务规则、领域模型） | 自己写 | 产品的差异化全在这里；核心域里的外部依赖是债 |

## 绝不自研清单（逐项为什么）

清单本体见[通用行为规则](../universal/principles.md) #8，此处每项补一行理由：

| 域 | 为什么绝不自研 |
| --- | --- |
| 加密/哈希 | 误用与侧信道：原语选对了，模式/填充/比较时序用错照样全盘皆输 |
| 鉴权协议（OAuth、JWT、session） | 规范细节即漏洞：alg=none、redirect_uri 校验这类坑藏在 RFC 脚注里 |
| 时区与日历运算 | 夏令时与历法边界：时区规则是政治决定、说改就改，靠 tzdata 不靠推理 |
| 货币精度计算 | 浮点精度：0.1 + 0.2 !== 0.3，金额没有「差不多对」 |
| SQL 转义 | 注入：手拼转义永远漏掉某种编码边角，参数化查询是唯一正解 |
| HTML 清洗 | XSS：浏览器解析器的怪癖多到任何自写正则白名单都会被绕过 |

## 反向规则：微依赖禁止

数行可实现、不在易错域、无需跟进上游变化的逻辑，不引包（principles #7）。

- ❌ 引 `is-odd` 判断奇偶　✅ `n % 2 !== 0`
- ❌ 为 clamp/chunk 一个函数引整个工具包　✅ 写进项目 utils，并登记到模块地图

## 栈文化差异

同一段逻辑在不同栈默认答案不同，以各栈 README 的「## 4. build-vs-buy 默认值」为准：

- [Go](../stacks/go/README.md)：标准库优先，自研阈值全库最高——先问 stdlib 有没有，再谈第三方。
- [TypeScript/React](../stacks/typescript-react/README.md)：生态默认用库，代价是传递依赖失控，引入前看一眼依赖树。
- [Python](../stacks/python/README.md)：居中——标准库覆盖面大，第三方质量参差，重点看维护状态。

## 版本与时效

- 选库先对当前栈 README 第 1 节的选型清单，清单外的候选才走上面的全套对比；不凭印象选「当年流行」的包。
- 写不熟或新版本的库 API 前先查官方文档（principles #6）——训练记忆里的 API 默认过期。
- 手搓后返工、引库后后悔，两类案例都记入[痛点日志](../docs/pain-log.md)，定期用它校准本文阈值与各栈第 4 节的默认值。
