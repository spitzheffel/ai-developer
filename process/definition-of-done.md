# 完成定义(Definition of Done)

「完成」不是感觉,是一组命令的退出码加上贴出来的输出。本文件是人读版本;机器强制版本是 `claude-code/hooks/stop-verify.sh`,说明见 [claude-code/hooks.md](../claude-code/hooks.md)——人会忘,钩子不会。

## 1. 「完成」的唯一定义

做哪几条看[任务简述](task-brief.md)的定级;改动碰到高风险路径(鉴权、金额、数据迁移、并发)一律按 L 级办,不看改动大小。第 2 节红线对所有档都生效。(来源:pain-log 2026-11-06)

| 档 | 必做 |
|---|---|
| S | 第 1–5 条,第 3 条只跑改动相关的测试;第 6 条只在布局或结构变化时做 |
| M | 六条全做,第 3 条至少跑完受影响模块的测试 |
| L 或高风险 | 六条全做,第 3 条跑全量测试 |

该档要求的条目缺一即未完成:

1. **lint 通过**:0 error。命令以所在栈文档「## 2. 工具链与命令」为准,如 [typescript-react](../stacks/typescript-react/README.md)。
2. **typecheck/编译通过**:退出码 0。
3. **测试通过**:范围按上表的档。
4. **贴出真实命令输出**:前三条必须贴出实际执行的命令与输出结尾,口头保证一律无效。
   - ❌ 「lint 和测试都没问题」
   - ✅ 「`npm test` → `Tests: 42 passed, 42 total`」(原样粘贴)
5. **新增逻辑有对应测试**:每个新函数、新分支至少被一个断言覆盖;改了行为必须同步改测试。
6. **UI 布局或结构改动附双视口截图自查**:用 Playwright 截 1280×800 与 375×812 两张改动后的页面,并确认 browser console 零错误,写一行自查结论,如「两视口渲染正常,无错位,console 0 error」。（〔试用〕来源:调研 2026-11,docs/research/adoption-plan.md）
   - 只改文案、颜色、图标这类不动布局的改动不截图(来源:pain-log 2026-11-06)。
   - 边界诚实:截图自查判得出布局错位,判不了「好看」;美观仍归人审。

## 2. 禁止清单(红线)

出现任意一条,无论其余检查多绿,直接打回:

| 红线 | 判定 |
|---|---|
| 跳过、删除、注释掉测试或断言 | diff 中有被删或被注释的 test / assert / expect |
| 加 skip/only 标记交差 | diff 新增 `.skip`、`.only`、`@pytest.mark.skip`、`t.Skip()` |
| 空实现或硬编码返回值糊弄测试 | 实现返回恰好满足断言的常量,如 `return true`、`return []` |
| 偷偷降低 lint/类型严格度 | 动了 eslint / tsconfig / pyproject / golangci 的严格项,或新增 ignore 注释,却没有单独说明 |

确需放宽某条检查:可以,但必须单独一条说明「改了哪项、为什么」,等你确认;不得夹在功能 diff 里。

## 3. 修 bug 铁律

三步,顺序不可颠倒,每步贴输出:

1. **先写复现**:最小的失败测试,贴出失败输出。
2. **再修**:只改实现,不动这个测试。
3. **展示同一测试转绿**:贴出通过输出。

没有「先失败」的修复不可信:既证明不了修的是这个 bug,也防不了它回归。

- ❌ 「找到原因修好了,顺手补了个测试」(该测试从未红过)
- ✅ 失败输出 → 修复 diff → 同一测试的通过输出,三段俱全

## 4. 提交规范(阶段6)

- **conventional commits**:`feat` / `fix` / `docs` / `refactor` / `test` / `chore` + 一句话描述。
  - ❌ `update`、`修改一下`
  - ✅ `fix: 订单金额改用银行家舍入`
- **原子提交 = 方案中的一步**:一个 commit 对应 [plan.md](../templates/plan.md.template) 的一个步骤,可独立 revert。
- **禁止混入**:无关文件、草稿、调试脚本、`.env` 与任何密钥。提交前过一遍 `git status`;该忽略的先补进 `.gitignore`。
- **PR 描述基于落盘的 plan.md 生成**:方案已落盘,PR 描述从它生成,不再凭记忆重新口述。

## 5. 基建提醒:检查必须快

测试慢到十分钟,人和 Claude Code 都会开始跳过它,DoD 名存实亡。发现检查变慢:优先修基建——只跑受影响测试、并行化、拆掉慢测试,并把这条记入 [痛点日志](../docs/pain-log.md)(pain log)。
